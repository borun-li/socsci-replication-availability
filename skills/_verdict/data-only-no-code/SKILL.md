# Scenario: DATA ONLY — data posted, no code

The deposit contains real data but no runnable analysis scripts. The opposite of
`code-available-data-restricted`: here you can load the data but must rebuild the
analysis yourself.

## How to recognize it
- `data/` contains real datasets (`.dta`, `.csv`, `.rda`, `.npy`, …).
- `code/` is empty, or holds only a README / codebook / documents — no `.do` / `.R` /
  `.py` scripts.
- Confirm by opening the folders separately (SOP §5) — an automated note that says
  "contains data but no code files" must be verified, not trusted.

## Notes for this corpus
None of the 8 manually reviewed articles ended here, but the SOP §4 verdict set includes
`DATA ONLY`, so this scenario is provided for completeness. Watch for packages where a
codebook or README in `code/` is mistaken for code.

## Handling steps
1. Verify the data are the real analysis data (row counts / IDs vs. the paper's tables).
2. Map the paper's Methods to the variables present; note which tables/figures could be
   regenerated by re-implementing the described models.
3. Record that code was "not posted / didn't find," not "doesn't exist" (SOP §4–5).

## Status classification
`DATA ONLY` — `code_availability: no`, `data_availability: yes`.

## Replication implication
Data-side reproducible, but every result requires re-implementing the analysis from the
manuscript. Treat any match as a re-analysis, not a code re-run.
